# 対称 SMP 版（`feat/smp-symmetric`）— 何を変えたか、何を比べるか

既定のカーネル（`manet-m14-udp`）は **ワーカ郵便箱方式**である。核 0 が OS 全体を
回し、核 1〜3 は WFE で待って、投函された範囲だけを計算して結果を返す
（`include/smp.h`, `smp_parallel_sum`）。仕事の割り当ては**投函時に静的に決まる**。

このブランチは **対称 SMP 方式**を加える。4 コアすべてがスケジューラを回し、
**共有 ready キューから自分でプロセスを取る**。偏りは走行中に均される。

## 比較の設計（同一カーネル・同一起動で A/B）

二次コアの待機ループは **郵便箱と ready キューの両方**を見る。したがって
一つのカーネルで両方式が動き、**焼き直しも再起動も挟まずに**比較できる。
これは重要で、当研究では「起動直後は 25〜35% 速い」という過渡が実測されており、
別々の起動で比べると方式の差と過渡が交絡する。

| 方式 | 口 | 割り当て |
|---|---|---|
| ワーカ郵便箱（従来） | `GET /nqpart?n=13&c0=..&c1=..`、`/bench` | 静的（範囲を投函） |
| 対称スケジューラ（新） | `GET /smpsched?n=13&tasks=8` | 動的（各コアが取る） |

`/smpsched` は `ran_per_core=a/b/c/d` を返す。**各コアが実際に処理したタスク数**で、
これが偏っていれば動的均衡が効いていない証拠になる。

## 実装

| 変更 | 内容 |
|---|---|
| `include/spinlock.h`, `system/spinlock.c` | チケットロック（LDAXR/STXR）と、原子命令を使わない Lamport のパン屋アルゴリズム。**この板は D-cache OFF なので、排他命令が効く保証がない**。どちらが正しいかは実機で `GET /smplock` が判定する |
| `include/smpsched.h`, `system/smpsched.c` | 対称スケジューラ本体、コアごとの idle、比較用 N-Queens |
| `system/proc.c` | ready キューをロックで保護。**ctxsw を跨いでロックを保持し、再開した側が離す**（xv6 と同じ受け渡し方式）。これをしないと「ready に戻したが SP をまだ書いていないプロセス」を他コアが拾う |
| `include/proc.h` | `currpid` をコアごとの別名に（左辺値のまま） |
| `system/ctxsw.S` | 新規プロセス用の入口 `proc_entry_trampoline_smp`（ロックを離してから実体へ） |
| `system/smp.c` | 二次コアはスケジューラを回す。郵便箱は `smp_worker_poll_once()` として残す |

## 意図的に対称化していない範囲（論文で明示すること）

- **デバイス・アクタ・ネットワーク・画面は核 0 だけ**が触る。再入可能でないため。
  核 1〜3 で走るプロセスは計算して終了するもの（`getmem`/`uart`/net を呼ばない）。
- **核 1〜3 にタイマ割り込みを配っていない**ので、そこで走るプロセスは自発的に
  終わるまで走る（ノンプリエンプティブ）。計算タスクの比較には十分だが、
  「対称 SMP スケジューラ」と名乗る際はこの限定を書くこと。

## 実機での確認手順

```sh
# 1. ロックが本当に効いているか（これが NG ならすべての測定が無意味）
curl 'http://192.168.3.101/smplock?n=20000'
#   → expected=80000 got=80000 OK        なら排他命令が効いている
#   → got がずれる                        なら SPIN_BAKERY で作り直す

# 2. 同一起動で二方式を比べる
curl 'http://192.168.3.101/nqpart?n=13&c0=0&c1=13'     # 静的分割
curl 'http://192.168.3.101/smpsched?n=13&tasks=4'      # 動的・タスク=コア数
curl 'http://192.168.3.101/smpsched?n=13&tasks=8'      # 動的・細粒度
curl 'http://192.168.3.101/smpsched?n=13&tasks=10'
```

**予想**（実測前に書いておく）: 列ごとの仕事量が不均一なので、
タスク数を増やすほど対称方式が有利になり、粒度を細かくしすぎると
ロックと切り替えの費用が効いて頭打ちになる。**その分岐点が測りたい量**である。

## ビルド

```sh
cd compile && make pi5              # 対称 SMP 版（既定）
cd compile && rm -rf obj/pi5 && make pi5 SMP_SYM=0   # 従来のワーカ型のみ
```

**`SMP_SYM` を切り替えるときは `rm -rf obj/pi5` が必須**。依存ファイルは CFLAGS の
変化を見ないので、混ざった像ができる。
